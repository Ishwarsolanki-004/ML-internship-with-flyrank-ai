Refresh Opportunity Scoring

A decision-support model for prioritizing content items that should be reviewed first for a potential refresh, using observed search-performance and recent-performance signals.

30,000 content items 32 clients 6 held-out clients Random Forest Human review required

Abstract

This study asks which content items should be reviewed first for a potential refresh based on observed search-performance and recent-performance signals. A repeatable ranking workflow was built from an anonymized FlyRank dataset, with identifiers and selected trend fields excluded from modeling to reduce leakage risk. A client-held-out validation design compared a Random Forest ranking against a transparent hand-written baseline using Precision@K. On the held-out set, the Random Forest measured 0.90, 0.92, 0.84 and 0.86 Precision@K at K=10, 25, 50 and 100, compared with 0.20, 0.16, 0.24 and 0.36 for the baseline. The result is a directional decision-support queue for human review, not a causal estimate of the effect of refreshing content.

1. Introduction / Problem Statement

Content teams often need to decide which pages deserve attention first when review capacity is limited. The decision supported here is prioritize content items for human review using a ranked queue and reason codes.

Automation boundary: This system is decision-support only. Human review is required before any content action, and automatic content changes are not allowed.

3. Methodology

Label and features

The target is the provided is_declining_label. The model uses the prepared feature vector while excluding the identifiers and selected trend fields listed above.

Baseline

The baseline is a transparent hand-written refresh score combining visibility, freshness risk, position opportunity, and depth-gap signals. Its weighting was visibility 0.40, freshness risk 0.30, position opportunity 0.25, and depth gap 0.05.

Validation design

The model predictions contain 27,675 training rows and 2,325 held-out rows. The held-out set contains 6 clients. The selected model was Random Forest, and every model-versus-baseline comparison below uses the same held-out rows.

Leakage checks

The workflow explicitly checked that content_id, client_id, trend_direction, and trend_pct were not used as model features.

5. Limitations & Honest Framing

  • The analysis does not estimate the causal impact of refreshing content.
  • The ranking identifies observed association with the supplied declining label; it does not prove why an item is declining.
  • Validation used 2,325 held-out rows from 6 clients, so generalization beyond this split should be tested before operational use.
  • Model probabilities are ranking signals and should not be treated as guaranteed probabilities of future decline.
  • The queue is intended for human review and decision-support, not automatic content changes.
  • Results may vary with data releases, preprocessing choices, feature definitions, and model-library versions.
Claim boundary: observed · measured · directional · decision-support. This work does not claim to prove Google's ranking algorithm or the causal effect of a refresh.

6. Ranked Recommendations

The final action queue contains 2,325 held-out items. Each item receives a model ranking, a reason code, and a suggested human-review action.

1

Visibility signal — 1,316 items

Review search visibility and position before deciding on a content change.

2

Recent decline signal — 911 items

Review recent performance and consider refresh only after human diagnosis.

3

Mixed or uncertain signal — 89 items

Manual diagnosis before action; available signals do not provide a clear single reason.

4

Freshness signal — 9 items

Review content freshness and determine whether an update is appropriate.

Recommended workflow: start with the highest-ranked items, inspect the supplied reason code and supporting signals, and then make a human decision about review, refresh, monitoring, or no action.
